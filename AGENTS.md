# Task Tracker: инструкция агенту

Task Tracker — персональная Windows-служба для папок задач и снимков Git-проектов. `src/ServiceHost.cs` держит службу, named pipe и локальный MCP endpoint; Python-код в `src/` выполняет операции. `bootstrap.ps1` и `scripts/` устанавливают их в защищённый Tracker. MCP-клиенты Codex живут в отдельном репозитории `ai-marketplace`.

## Работа с репозиторием

- Перед изменением прочитай [README.md](README.md) и код затрагиваемого пути. Для установки открой [docs/admin-bootstrap.md](docs/admin-bootstrap.md) и [docs/install-v3.md](docs/install-v3.md); для Python — [docs/python-runtime.md](docs/python-runtime.md).
- Проследи полный путь изменения: bootstrap → защищённый wrapper → установщик → служба → Python worker → MCP-клиент. Проверяй только затронутые звенья и связанные тесты.
- Пути пользователя бери из профиля `TargetUser` и его `.env/env.txt`: `TRACKER_FOLDER` задаёт Tracker, `GIT_FOLDER` — корень снимков по умолчанию. Вложенные пути строй от этих корней, каталога репозитория или каталога установленной службы; не закрепляй путь конкретной машины.
- Корневой `AGENTS.md` относится к разработке этого репозитория. [templates/AGENTS.md](templates/AGENTS.md) устанавливается в `tasks/AGENTS.md` и относится к работе внутри папок задач.

## Сопровождение установки

1. Сначала объясни пользователю одним абзацем, зачем нужен запуск: он проверит чистую `main` и локальную `origin/main`, профиль и пути `TargetUser`, права Tracker, подготовит защищённый Python runtime, затем установит или обновит службу с возможностью отката. Покажи, какие значения берутся из `.env/env.txt`; токен не выводи.
2. Проверь предпосылки по README: Windows, PowerShell 7, Git, нужная версия Python из `.venv/python_version.txt`, доступный `py.exe`, целевой пользователь, `TRACKER_FOLDER` и `GIT_FOLDER` либо явный `-SnapshotRoots`. Компилятор C# нужен при первой сборке или изменении host. До запуска покажи пользователю конкретную команду и ожидаемые изменения.
3. Повышенный запуск выполняет пользователь из корня чистого репозитория: `pwsh -NoProfile -File .\bootstrap.ps1 -TargetUser 'DOMAIN\User'`. Не обходи проверки Git и не запускай отдельные внутренние скрипты вместо корневого bootstrap. Если репозиторий грязный или HEAD не совпадает с локальной `origin/main`, сначала помоги устранить причину.
4. По выводу различай успех службы и доступность инструментов Codex. Установщик проверяет запуск службы и MCP с токеном, но не устанавливает плагины. Целевой пользователь проверяет плагины из `ai-marketplace`, при необходимости обновляет их, полностью перезапускает Codex и проверяет инструменты в новой беседе.
5. При ошибке назови остановившийся этап, что уже могло измениться и что проверить дальше. Используй таблицу ошибок README и признаки отката из `docs/install-v3.md`; при `RECOVERY_INCOMPLETE` сначала разбери сохранённое состояние. Не проси повторять установку вслепую.

Завершение: пользователь понимает, где расположены его данные и runtime, кто выполняет код, что проверил установщик, что осталось проверить в Codex и как действовать при ошибке.
