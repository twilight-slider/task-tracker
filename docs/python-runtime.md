# Python runtime службы

Пользователь самостоятельно устанавливает Python 3.11 и настраивает `PATH` так, чтобы `python.exe` в повышенной консоли указывал на эту версию. Установщик создаёт виртуальное окружение в `<Tracker>\.protected\runtime` из найденного Python и выполняет `pip install -r requirements.txt`. Служба запускает `<Tracker>\.protected\runtime\Scripts\python.exe` с ключом `-I`. Код worker находится в `<Tracker>\.protected\bin`; рабочий клон и корневая `.venv` используются только при разработке и тестировании.

Python и PyYAML не поставляются репозиторием TaskTracker. Целостность установленного Python и загружаемых pip библиотек находится вне задачи Tracker. `requirements.txt` закрепляет требуемую версию PyYAML. Виртуальное окружение использует базовую установку Python; её нельзя удалять после установки Tracker.

`scripts/Stage-PythonRuntime.ps1` принимает пустой каталог staging, проверяет Python 3.11 из `PATH`, создаёт venv, устанавливает зависимости pip и проверяет импорт `yaml` с `-I`. Установщик вызывает его до остановки действующей службы и переносит в защищённый runtime только успешно подготовленное окружение. Если Python, pip или загрузка зависимостей недоступны, установка останавливается до переключения службы.

Проверка в репозитории: `pwsh -NoProfile -File tests/test-stage-python-runtime.ps1`. Если индекс pip недоступен в тестовой среде, можно передать путь к заранее полученному wheel через `TRACKER_TEST_WHEEL_DIR`. Это влияет только на тест; рабочий установщик использует обычные настройки pip. Файлы проверки остаются в `.runtime/tests/stage-python-runtime/`.
