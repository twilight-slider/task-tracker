# Python runtime службы

Пользователь самостоятельно устанавливает Python 3.11 с Windows Python launcher. Установщик находит `py.exe` через системный поиск команд и выбирает `py -3.11`, даже если обычный `python` в `PATH` указывает на другую версию. Путь к launcher и Python конкретного компьютера в коде не закреплён. Из выбранного Python установщик создаёт виртуальное окружение в `<Tracker>\.protected\runtime` и выполняет `pip install -r requirements.txt`. Служба запускает `<Tracker>\.protected\runtime\Scripts\python.exe` с ключом `-I`. Код worker находится в `<Tracker>\.protected\bin`; рабочий клон и корневая `.venv` используются только при разработке и тестировании.

Python и PyYAML не поставляются репозиторием TaskTracker. Целостность установленного Python и загружаемых pip библиотек находится вне задачи Tracker. `requirements.txt` закрепляет требуемую версию PyYAML. Виртуальное окружение использует базовую установку Python; её нельзя удалять после установки Tracker.

`scripts/Stage-PythonRuntime.ps1` принимает пустой каталог staging, проверяет выбранный launcher Python 3.11, создаёт venv, устанавливает зависимости pip и проверяет импорт `yaml` с `-I`. Установщик вызывает его до остановки действующей службы и переносит в защищённый runtime только успешно подготовленное окружение. Если launcher, Python, pip или загрузка зависимостей недоступны, установка останавливается до переключения службы.

Проверка в репозитории: `pwsh -NoProfile -File tests/test-stage-python-runtime.ps1`. Если индекс pip недоступен в тестовой среде, можно передать путь к заранее полученному wheel через `TRACKER_TEST_WHEEL_DIR`. Это влияет только на тест; рабочий установщик использует обычные настройки pip. Файлы проверки остаются в `.runtime/tests/stage-python-runtime/`.
