# Python runtime службы

Пользователь самостоятельно устанавливает Python с Windows Python launcher. Требуемая версия задаётся в версионируемом `.venv/python_version.txt`; сейчас это `python3.11`. Установщик находит `py.exe` через системный поиск команд и выбирает указанную версию, даже если обычный `python` в `PATH` указывает на другую. Путь к launcher и Python конкретного компьютера в коде не закреплён. Из выбранного Python установщик создаёт виртуальное окружение в `<Tracker>\.protected\runtime` и выполняет `pip install -r requirements.txt`. Служба запускает `<Tracker>\.protected\runtime\Scripts\python.exe` с ключом `-I`. Код worker находится в `<Tracker>\.protected\bin`; рабочий клон и корневая `.venv` используются только при разработке и тестировании.

Python и PyYAML не поставляются репозиторием TaskTracker. Установщик не скачивает и не устанавливает сам Python; `py -0p` только проверяет, что заданная версия уже зарегистрирована. Целостность установленного Python и загружаемых pip библиотек находится вне задачи Tracker. `requirements.txt` закрепляет требуемую версию PyYAML, которую pip устанавливает в venv. Виртуальное окружение использует базовую установку Python; её нельзя удалять после установки Tracker.

`scripts/Stage-PythonRuntime.ps1` принимает пустой каталог staging и проверяет через launcher строго версию из файла настройки. Если её нет, сценарий сообщает, что нужно установить эту версию или изменить настройку; рекомендуется 3.11. На другую установленную версию он автоматически не переключается. Python не скачивается и не устанавливается. Выбранный Python создаёт venv, pip устанавливает зависимости и проверяется импорт `yaml` с `-I`. Установщик вызывает этот этап до остановки действующей службы и переносит в защищённый runtime только успешно подготовленное окружение. Если нужной версии, launcher, pip или зависимостей нет, установка останавливается до переключения службы. То же правило без fallback действует для тестовой корневой `.venv`.

Проверка в репозитории: `pwsh -NoProfile -File tests/test-stage-python-runtime.ps1`. Если индекс pip недоступен в тестовой среде, можно передать путь к заранее полученному wheel через `TRACKER_TEST_WHEEL_DIR`. Это влияет только на тест; рабочий установщик использует обычные настройки pip. Файлы проверки остаются в `.runtime/tests/stage-python-runtime/`.
