# Матрица прав папок задач

Bootstrap принимает имена учётных записей: `-TargetUser` для клиента Tracker, `-ServiceAccountName` для службы и `-WorkspaceAgentUsers` для рабочих агентов. Имена сохраняются вместе с проверенными SID. Рабочие агенты не получают доступ к named pipe службы или её защищённой конфигурации.

Установщик сохраняет `taskAclMatrix` в защищённом `service.json`. Каждая строка содержит имя, SID и собственные права на дерево задач, каталоги задачи, файлы и защищённые каталоги. Начальные значения:

| Учётная запись | tasks и год | Каталоги задачи | Файлы задачи | .protected |
| --- | --- | --- | --- | --- |
| SYSTEM | Полный доступ | Полный доступ | Полный доступ | Полный доступ |
| Administrators | Полный доступ | Полный доступ | Полный доступ | Полный доступ |
| Служба Tracker | Полный доступ | Полный доступ | Полный доступ | Полный доступ |
| TargetUser | Чтение и проход | Чтение, проход, создание файлов | Полный доступ | Нет разрешений |
| Каждая WorkspaceAgentUsers | Чтение и проход | Чтение, проход, создание файлов | Полный доступ | Нет разрешений |

Совпадение начальных значений клиента и рабочего агента не связывает их права. Каждая учётка получает значения своей строки. Не доверенным учёткам нельзя выдать удаление каталогов, изменение их ACL или владельца: иначе они смогут нарушить защиту вложенных папок.

Новая задача получает права до успешного ответа операции создания. Для существующей задачи `ensure_task_acl(key)` находит её в исходном году, проверяет путь и применяет ту же матрицу; новую задачу эта операция не создаёт. Train Driver вызывает её перед каждой записью TRAINRUN через общий путь сохранения, включая ручные переходы и автоматическую блокировку. Ошибка применения прав останавливает запись TRAINRUN.

Существующие защищённые ACL и владельцы `.protected` сохраняются, в том числе во вложенных обычных каталогах. У новых защищённых каталогов сначала закрывается наследование, затем выдаются права обычным родителям. Владельцем обычных каталогов остаётся служба. Повторное применение разрешено. При обновлении установленная валидная строка сохраняется по SID; начальные значения добавляются только новым учёткам.

Обновление требует согласованных версий службы Tracker и Train Driver: старый Tracker без `ensure_task_acl` отклонит новую запись TRAINRUN. Установка выполняется штатным корневым bootstrap из чистой main; редактирование checkout не обновляет работающую службу.

Имена передаются явно, например:

```powershell
$ClientUser = 'VASIL\Vasil'
$ServiceAccountName = 'Vasil-Task-Tracker'
$WorkspaceAgentUsers = @('VASIL\Vasil-AI-Agent')
./bootstrap.ps1 -TargetUser $ClientUser -ServiceAccountName $ServiceAccountName -WorkspaceAgentUsers $WorkspaceAgentUsers
```

При переустановке без `-WorkspaceAgentUsers` сохраняется установленный список; явный пустой список удаляет рабочие учётки из политики задач. SID клиента named pipe при этом не заменяется SID рабочего агента.
