# Проверка границы прав Windows

`tests/probe-windows-boundary.ps1` проверяет права и локальный канал на рабочей машине. Это стенд, использованный до установки MCP-службы; его результаты не заменяют проверку установленного сервиса.

## Тест 1: сервис `VASIL\TaskFolderMcpSvc` и обычный агент `VASIL\Vasil`

Для первоначального стенда учётная запись `VASIL\TaskFolderMcpSvc` была создана сценарием `scripts/New-TaskFolderMcpAccount.ps1` в локальной группе администраторов. Установщик MCP-службы удаляет её из этой группы и назначает необходимые права на защищённый каталог напрямую.

### Результат повышенного сеанса

Сервис под высоким уровнем целостности создал защищённый каталог и именованный канал. Клиент из песочницы Codex получил `Access denied` при подключении; прямые операции с файлами были запрещены. Первый стенд продолжил ждать соединение в блокирующем вызове; следующие запуски используют прерываемое ожидание с пределом 10 минут. Причину отказа нельзя приписывать уровню целостности без повторного прогона вне песочницы.

### Следующая проверка: отдельная учётная запись без повышения

Из обычного сеанса выполните `runas /user:VASIL\TaskFolderMcpSvc "pwsh -NoProfile"` и введите пароль. В открывшемся окне `whoami` должен показать `vasil\taskfoldermcpsvc`, а `whoami /groups` — средний уровень целостности (`S-1-16-8192`). **Не повышайте это окно через UAC.** Выполните:

```powershell
pwsh -NoProfile -File 'D:\Projects\Git\ai-reps\task-folder-mcp\tests\probe-windows-boundary.ps1' -Mode Server -AgentAccount 'VASIL\Vasil' -ProtectedRoot 'C:\ProgramData\AIDEV58-boundary-test1b\protected'
```

Повтор под отдельной неповышенной учётной записью прошёл: клиент `VASIL\Vasil` со средним уровнем целостности, запущенный вне песочницы Codex, получил ответ по именованному каналу. Запись, удаление, переименование и изменение ACL были запрещены; исходный `sentinel.txt` сохранился. Тот же клиент из песочницы Codex получал `Access denied` при подключении к каналу. Родительский каталог `C:\ProgramData\AIDEV58-boundary-test1b` и данные теста не удалены.

Для первоначального варианта теста 1 оставалась отдельная проверка повышенного сервера с новым корнем и неповышенным клиентом вне песочницы. После подготовки MCP-службы приоритет имеет проверка установленного сервиса и его каталогов. Команда для исторического стенда:

```powershell
pwsh -NoProfile -File 'D:\Projects\Git\ai-reps\task-folder-mcp\tests\probe-windows-boundary.ps1' -Mode Server -AgentAccount 'VASIL\Vasil' -ProtectedRoot 'C:\ProgramData\AIDEV58-boundary-test1c\protected'
```

Успех стенда показывает изоляцию от **обычного процесса** `VASIL\Vasil`. Он не доказывает защиту от процесса, который пользователь самостоятельно повысил через UAC, и не заменяет проверку установленной службы или тест 2.

## Тест 2: отложен

Когда будет готова учётная запись `VASIL\Vasil-AI-Agent`, тот же стенд проверит её токен отдельно. Сейчас тест 2 не запускается.
